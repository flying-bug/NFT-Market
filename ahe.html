JSP & Servlet: Công Nghệ Web Động

Tổng hợp kiến thức cốt lõi, vòng đời, quản lý phiên và mô hình MVC trong phát triển ứng dụng Java Web.

1. Tổng Quan & So Sánh

☕ JSP (JavaServer Pages) là gì?

Là một công nghệ Java cho phép tạo các trang web động bằng cách nhúng mã Java trực tiếp vào mã HTML.

Mục đích chính: Tạo giao diện người dùng (UI) trên các ứng dụng web để hiển thị thông tin trực quan cho Client.

⚙️ Servlet là gì?

Là các lớp Java chạy trên máy chủ (Server-side class), kế thừa các chức năng để tiếp nhận các yêu cầu HTTP và trả về các phản hồi phù hợp.

Mục đích chính: Xử lý logic nghiệp vụ (business logic), kiểm soát luồng điều hướng, và tương tác trực tiếp với cơ sở dữ liệu.

Sự Khác Biệt Chính giữa JSP và Servlet

JSP: Tập trung vào giao diện (View), dễ viết code HTML hơn, thích hợp để hiển thị dữ liệu.

Servlet: Tập trung vào logic điều khiển (Controller), cấu trúc code Java hoàn chỉnh, tối ưu cho xử lý dữ liệu.

* Lưu ý: Thực chất JSP sẽ được Web Container dịch ra thành Servlet ở phía sau, vì vậy chúng có khả năng thực hiện mọi tác vụ tương đương Servlet.

2. Vòng Đời (Lifecycle)

Vòng Đời của JSP
  • Translation (Dịch): Container phân tích mã JSP và dịch nó thành một mã nguồn Servlet (.java).
  • Compilation (Biên dịch): Mã nguồn Servlet được biên dịch thành file bytecode (.class).
  • Loading (Nạp): Bytecode của Servlet được nạp vào bộ nhớ JVM của Container.
  • Instantiation (Khởi tạo đối tượng): Tạo thực thể Servlet thông qua hàm constructor.
  • Initialization (Cấu hình): Container gọi phương thức init() để thiết lập cấu hình ban đầu.
  • Request Processing (Xử lý yêu cầu): Đối với mỗi yêu cầu của client, container gọi phương thức service() (tương ứng gọi doGet(), doPost(), v.v.).
  • Destruction (Hủy bỏ): Khi ứng dụng ngừng chạy, container gọi phương thức destroy() để giải phóng tài nguyên.
Vòng Đời của Servlet
  • init(ServletConfig): Được gọi duy nhất 1 lần khi servlet được tải vào bộ nhớ để thiết lập tài nguyên khởi tạo ban đầu.
  • service(request, response): Được gọi nhiều lần, mỗi lần có yêu cầu HTTP gửi đến. Nó xác định loại phương thức HTTP để phân luồng đến doGet(), doPost().
  • destroy(): Được gọi 1 lần khi đóng máy chủ hoặc giải phóng bộ nhớ để đóng kết nối, lưu log hoặc dọn dẹp các tài nguyên.

3. Thẻ Hành Động (Action Tag)

Action Tags trong JSP là các thẻ XML đặc biệt cho phép lập trình viên thực hiện các tác vụ động như nhúng một trang khác, truyền tham số, hoặc điều hướng trang mà không cần viết mã Java thô trực tiếp.

Thẻ Hành Động Mô Tả Ví Dụ Sử Dụng
<jsp:include> Nhúng nội dung của một tài nguyên khác (JSP, HTML hoặc Servlet) vào trang hiện tại lúc runtime. <jsp:include page="header.jsp" />
<jsp:forward> Chuyển hướng (forward) yêu cầu hiện tại đến một tài nguyên khác cùng máy chủ mà không làm thay đổi URL trên trình duyệt client. <jsp:forward page="login.jsp" />
<jsp:param> Truyền tham số (cặp name-value) vào trong thẻ include hoặc forward. 
<jsp:forward page="login.jsp">
    <jsp:param name="username" value="JohnDoe" />
</jsp:forward>

4. Scripting Elements trong JSP

Cho phép chèn mã nguồn Java trực tiếp vào tài liệu JSP. Gồm 3 loại chính sau đây:

1. Declaration (Khai báo)

Khai báo biến hoặc phương thức ở cấp độ lớp Servlet được sinh ra (instance variables/methods). Có phạm vi hoạt động trên toàn trang JSP.

Cú pháp: <%! ... %>

JSP Declaration Example 
<%!
    int counter = 0;
    public void incrementCounter() {
        counter++;
    }
%>
2. Expression (Biểu thức)

Đánh giá một biểu thức Java và chuyển kết quả thành chuỗi để in trực tiếp ra trang HTML output. Không dùng dấu chấm phẩy ở cuối.

Cú pháp: <%= ... %>

JSP Expression Example 
<%= "Hello, World!" %>
<%= counter %>
3. Scriptlet (Mã lệnh)

Chèn trực tiếp các khối mã Java thực thi vào trong phương thức xử lý yêu cầu _jspService() của Servlet.

Cú pháp: <% ... %>

JSP Scriptlet Example 
<%
    String username = request.getParameter("username");
    if (username != null) {
        out.println("Hello, " + username);
    } else {
        out.println("Hello, Guest");
    }
%>

5. Đối Tượng Ẩn (Implicit Objects)

JSP cung cấp 9 đối tượng đặc biệt đã được container khai báo sẵn mà lập trình viên có thể gọi ra và dùng trực tiếp bất kỳ lúc nào.

Tên Đối Tượng Kiểu Class / Interface Mô Tả Chức Năng Ví Dụ Thực Tế
request HttpServletRequest Đại diện cho yêu cầu HTTP từ phía client (chứa các parameter, header, cookies). request.getParameter("username")
response HttpServletResponse Đại diện cho phản hồi gửi về client, dùng để cấu hình Header, redirect, content-type. response.setContentType("text/html")
session HttpSession Lưu trữ dữ liệu duy trì trạng thái của người dùng qua nhiều request khác nhau. session.setAttribute("user", obj)
application ServletContext Cung cấp phạm vi dữ liệu rộng nhất, chia sẻ thông tin trên toàn bộ ứng dụng web. application.setAttribute("appData", data)
out JspWriter Luồng ghi dữ liệu trực tiếp lên trang phản hồi HTML của trình duyệt. out.println("Hello World")
config ServletConfig Chứa thông tin tham số khởi tạo (init parameters) của Servlet/JSP đó. config.getInitParameter("name")
pageContext PageContext Tham chiếu ngữ cảnh trang, giúp quản lý và truy xuất đến mọi scope và đối tượng khác. pageContext.forward("target.jsp")
page Object Tham chiếu đến chính thực thể Servlet hiện tại (tương tự như từ khóa this). page.hashCode()
exception Throwable Chỉ khả dụng trong các trang có cấu hình isErrorPage="true" để lấy thông tin lỗi. exception.getMessage()

★ Cải Tiến: JSTL & Expression Language (EL)

Trong các dự án Java Web thực tế và đề thi PRJ301, lập trình viên bắt buộc phải hạn chế viết mã Java thô (Scriptlet) trong JSP bằng cách chuyển sang sử dụng JSTL (JSP Standard Tag Library) và EL (Expression Language) để làm mã nguồn sạch sẽ, dễ bảo trì hơn.

⚡ 1. Expression Language (EL)

Cung cấp khả năng truy cập đơn giản và nhanh chóng vào dữ liệu nằm trong các đối tượng Java (JavaBeans) và các phạm vi lưu trữ (Scopes).

Cú pháp: ${expression}

Ví dụ: Thay thế <%= session.getAttribute("username") %> bằng ${sessionScope.username}.

🏷️ 2. JSTL Core Tags

Thư viện thẻ tiêu chuẩn hỗ trợ lập trình cấu trúc điều kiện, vòng lặp và quản lý URL một cách tường minh.

Khai báo thư viện ở đầu trang JSP:

<%@ taglib prefix="c" uri="http://java.sun.com/jsp/jstl/core" %>
Ví Dụ So Sánh Trực Quan
Nhiệm Vụ Cách Dùng Scriptlet (Cũ - Rối Code) Cách Dùng JSTL & EL (Hiện Đại - Sạch Sẽ)
Hiển thị biến 
<%
  User u = (User)request.getAttribute("user");
  out.print(u.getName());
%>
 
${user.name}
Kiểm tra điều kiện 
<% if (role.equals("admin")) { %>
  <h1>Chào Admin</h1>
<% } %>
 
<c:if test="${user.role == 'admin'}">
  <h1>Chào Admin</h1>
</c:if>
Vòng lặp danh sách 
<%
  List<Item> list = (List)request.getAttribute("items");
  for(Item i : list) {
    out.print(i.getName());
  }
%>
 
<c:forEach var="item" items="${items}">
  ${item.name}
</c:forEach>

6. Servlet API & Cấu Trúc Dự Án

Servlet API là tập hợp các giao diện và lớp phục vụ xây dựng và quản trị vòng đời ứng dụng trên máy chủ web:

Các Class & Interface Cốt Lõi

Servlet: Giao diện định nghĩa các phương thức vòng đời cốt lõi: init(), service(), destroy().

HttpServlet: Lớp cơ sở (Abstract Class) mở rộng hỗ trợ trực tiếp giao thức HTTP (cung cấp doGet, doPost, v.v.).

ServletRequest / ServletResponse: Cung cấp thông tin truy vấn và tạo phản hồi gửi về client.

Cấu Trúc Thư Mục Chuẩn (Java Web Project)
project-root/
│
├── src/                    // Chứa mã nguồn java (.java)
├── WEB-INF/                // Thư mục ẩn bảo mật ứng dụng
│   ├── web.xml             // File cấu hình Deployment Descriptor
│   ├── classes/            // Chứa các file biên dịch (.class)
│   └── lib/                // Chứa thư viện bổ trợ (.jar)
└── META-INF/               // Chứa metadata cấu hình bổ sung

Tomcat Server: Là một Web Container / Servlet Container phổ biến để thực thi mã nguồn Java Web, quản lý toàn bộ vòng đời của các Servlet và phân phối các yêu cầu HTTP đến các ứng dụng web tương ứng.

7. ServletContext, Request & Response

Quản lý vòng đời dữ liệu và chia sẻ thông tin dựa trên các đối tượng trung gian:

ServletContext

Là một thực thể đại diện cho môi trường hoạt động của ứng dụng, dùng để cấu hình toàn cục hoặc chia sẻ dữ liệu giữa các Servlet trong cùng ứng dụng.

ServletContext Example 
ServletContext context = getServletContext();
context.setAttribute("myData", "Shared Value");

// Lấy dữ liệu ở Servlet khác
String data = (String) context.getAttribute("myData");
HttpServletRequest & Response

Request: Lấy thông tin từ Client gửi lên (parameter, cookies, attribute).

Response: Thiết lập dữ liệu và kiểu định dạng (ContentType) gửi về trình duyệt của khách hàng.

Request & Response Example 
protected void doGet(HttpServletRequest request, HttpServletResponse response) 
    throws ServletException, IOException {
    
    String user = request.getParameter("username");
    response.setContentType("text/html");
    PrintWriter out = response.getWriter();
    out.println("<h1>Welcome, " + user + "</h1>");
}

Phạm vi lưu trữ dữ liệu (Scopes) trong Java Web

Khi lưu trữ thuộc tính (Attributes) để chuyển giao dữ liệu giữa các trang, ta có 4 phạm vi khác nhau với thời gian sống xác định:

Scope Name Thời Gian Sống (Lifetime) Cách Lấy Đối Tượng Mục Đích Sử Dụng
Page Chỉ tồn tại trong trang JSP hiện tại. pageContext Lưu các biến tạm thời trong trang.
Request Tồn tại trong suốt một chu kỳ yêu cầu của client (Request-Response cycle), bao gồm cả các trang được forward. request Chuyển dữ liệu từ Servlet sang trang JSP hiển thị.
Session Tồn tại trong suốt phiên làm việc của một người dùng cụ thể (từ khi truy cập đến khi tắt trình duyệt hoặc timeout). request.getSession() Lưu trữ thông tin đăng nhập, giỏ hàng người dùng.
Application Tồn tại từ lúc Server khởi chạy đến khi Server tắt (Chia sẻ cho toàn bộ người dùng). getServletContext() Lưu các cấu hình dùng chung, số lượt truy cập ứng dụng.
⚡ Điểm Cốt Lõi: So Sánh Forward và SendRedirect
Đặc Điểm So Sánh Forward (RequestDispatcher) SendRedirect (HttpServletResponse)
Nơi xử lý Hoàn toàn xử lý ở phía Server. Được chuyển tiếp về Client xử lý lại.
Địa chỉ URL Không thay đổi trên thanh địa chỉ. Thay đổi sang URL mới.
Vòng đời Request Giữ nguyên đối tượng Request ban đầu (chuyển tiếp tiếp). Tạo ra một Request hoàn toàn mới.
Hiệu năng Nhanh hơn vì không cần phản hồi về client. Chậm hơn vì cần hai vòng Request-Response.
Cú pháp code 
request.getRequestDispatcher("url")
       .forward(request, response);
 
response.sendRedirect("url");

8. Mô Hình MVC & Kiến Trúc Phát Triển

MVC (Model-View-Controller) là mô hình kiến trúc phần mềm giúp phân chia ứng dụng thành 3 thành phần chính tách biệt để dễ kiểm soát và phát triển:

Thành Phần Trong MVC

Model: Đại diện cho dữ liệu và các quy tắc nghiệp vụ (Database, Business Logic Class, DAO, DTO).

View: Hiển thị giao diện người dùng và tiếp nhận thao tác nhập dữ liệu (thường là các trang JSP, HTML).

Controller: Cầu nối điều khiển luồng, nhận các yêu cầu HTTP, thao tác trên Model, điều hướng đến View hiển thị (thường là các Servlet).

Quy Trình Tương Tác MVC
  • Client tương tác trên View, gửi Request.
  • Controller tiếp nhận Request, xử lý điều hướng và gọi Model xử lý dữ liệu.
  • Model cập nhật trạng thái dữ liệu (lấy từ DB).
  • Controller lựa chọn trang View thích hợp để hiển thị dữ liệu đã cập nhật.
  • View hiển thị và kết thúc luồng xử lý.

Sơ Đồ Tương Tác MVC Trực Quan

1. View (Trình Duyệt)

Gửi HTTP Request của người dùng đi.

➡️
2. Controller (Servlet)

Nhận Request, gọi Model phù hợp.

➡️
3. Model (DAO/DB)

Tải dữ liệu DB, trả về cho Controller.

So Sánh JSP Model 1 và Model 2

JSP Model 1: JSP kiêm nhiệm cả logic nghiệp vụ (Controller/Model) lẫn hiển thị (View). Kiến trúc này đơn giản nhưng dễ gây rối code, khó bảo trì.

JSP Model 2 (MVC chuẩn): Tách biệt rõ ràng. Servlet đóng vai trò Controller điều khiển luồng, JSP đóng vai trò View hiển thị, và các JavaBean/DAO xử lý dữ liệu (Model). Đây là kiến trúc tối ưu được khuyến cáo.

9. Quản Lý Phiên Làm Việc (Session Management)

HTTP là giao thức Stateless (không trạng thái), vì vậy máy chủ không tự nhớ được Client. Để duy trì trạng thái của người dùng qua các trang khác nhau (giỏ hàng, trạng thái đăng nhập), ta có 4 giải pháp:

1. Cookies

Là các tệp văn bản nhỏ được lưu trên trình duyệt của client. Dùng để lưu trữ thông tin tùy chọn, ghi nhớ trạng thái phiên làm việc.

Cookie Code Example 
// 1. Tạo Cookie
Cookie cookie = new Cookie("username", "JohnDoe");
cookie.setMaxAge(60*60*24); // 1 ngày
response.addCookie(cookie);

// 2. Đọc Cookie
Cookie[] cookies = request.getCookies();
for(Cookie ck : cookies){
    if(ck.getName().equals("username")){
        out.print(ck.getValue());
    }
}

// 3. Xóa Cookie
cookie.setMaxAge(0);
response.addCookie(cookie);
2. HttpSession

Cơ chế lưu trữ trạng thái người dùng an toàn trên máy chủ. Trình duyệt client chỉ lưu mã Session ID duy nhất trong Cookie.

HttpSession Code Example 
// Khởi tạo / Lấy phiên hiện tại
HttpSession session = request.getSession();

// Thiết lập dữ liệu vào session
session.setAttribute("username", "JohnDoe");

// Đọc dữ liệu từ session
String user = (String) session.getAttribute("username");

// Hủy / Xóa phiên làm việc
session.invalidate();
3. URL Rewriting

Kỹ thuật gắn trực tiếp ID phiên làm việc vào cuối các đường dẫn URL của trang web. Hữu ích khi client tắt chế độ lưu trữ Cookie trên trình duyệt.

Cú pháp: response.encodeURL("welcome.jsp")

4. Hidden Form Fields

Sử dụng các trường ẩn trong HTML Form để truyền Session ID hoặc các trạng thái dữ liệu ngầm từ trang này sang trang khác khi submit biểu mẫu.

<form action="process.jsp" method="post">
    <input type="hidden" name="sessionId" value="abc123">
    <input type="text" name="username">
    <input type="submit" value="Submit">
</form>

10. Bộ Lọc (Filter) & Xử Lý Lỗi

Bộ Lọc (Filter Lifecycle)

Filter được sử dụng để can thiệp, kiểm tra hoặc chỉnh sửa các yêu cầu và phản hồi trước/sau khi chúng đi qua Servlet hoặc JSP (ví dụ: Logging, Authentication, UTF-8 Encoding).

  • init(FilterConfig): Khởi tạo Filter.
  • doFilter(req, res, chain): Thao tác tiền xử lý, sau đó gọi chain.doFilter(request, response) để đẩy request đi tiếp, sau đó hậu xử lý phản hồi.
  • destroy(): Hủy Filter và giải phóng tài nguyên.
Xử Lý Lỗi (Exception Handling)

Trong JSP: Sử dụng cài đặt <error-page> trong file cấu hình web.xml để tự động chuyển tiếp tới trang hiển thị lỗi thân thiện.

Trong Servlet: Thực hiện khối try-catch-finally trong mã nguồn Java, chuyển tiếp tới trang lỗi qua cơ chế Dispatcher:

request.getRequestDispatcher("/error.jsp")
       .forward(request, response);

Luồng Xử Lý Đi Qua Filter Chain

1. Client Request

Gửi từ trình duyệt Browser.

➡️
2. Filter (Tiền Xử Lý)

Đọc mã hóa, kiểm quyền.

➡️
3. Servlet / JSP

Xử lý logic, tạo nội dung.

➡️
4. Filter (Hậu Xử Lý)

Log dữ liệu, nén Response.

Mẫu Triển Khai Filter trong Java Servlet
Filter Implementation Example 
public class MyFilter implements Filter {
    public void init(FilterConfig config) throws ServletException {
        // Cấu hình khởi tạo ban đầu
    }
    
    public void doFilter(ServletRequest request, ServletResponse response, FilterChain chain)
        throws IOException, ServletException {
        
        // Tiền xử lý: Ví dụ thiết lập mã hóa UTF-8
        request.setCharacterEncoding("UTF-8");
        
        // Chuyển request đến điểm xử lý tiếp theo
        chain.doFilter(request, response);
        
        // Hậu xử lý (nếu có)
    }
    
    public void destroy() {
        // Giải phóng tài nguyên dọn dẹp bộ nhớ
    }
}

11. Mô Hình Kiến Trúc Client-Server

Mô hình cơ bản trong môi trường lập trình Web:

Khái Niệm Thành Phần

Client (Trình duyệt/Ứng dụng di động): Thực hiện gửi các truy vấn, yêu cầu tài nguyên đến máy chủ qua kết nối mạng mạng (yêu cầu HTTP).

Server (Tomcat/Máy chủ Web): Thực hiện lắng nghe, xử lý logic, truy vấn cơ sở dữ liệu nếu có và đóng gói dữ liệu phản hồi (Response) trả ngược về Client.

Các Bước Giao Tiếp HTTP
  • Client gửi một yêu cầu (HTTP Request) đến Server.
  • Server phân tích và xử lý logic (đọc dữ liệu DB, tính toán logic).
  • Server chuẩn hóa dữ liệu đầu ra và phản hồi lại Client (HTTP Response).
  • Client (Web Browser) nhận phản hồi, phân tách mã HTML/CSS/JS để kết xuất giao diện trực quan cho người dùng.
